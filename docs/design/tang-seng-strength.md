## 1. 背景与结论

### 1.1 现状（已实现）

| 等级   | 实现              | 关键参数（`difficulty.ts`）                                     |
| ------ | ----------------- | --------------------------------------------------------------- |
| 沙和尚 | `ShaHeshangAgent` | Top-K + 必应紧急威胁（含活三修复）                              |
| 猪八戒 | `HeuristicAgent`  | 0 层赢法启发                                                    |
| 孙悟空 | `MinimaxAgent`    | `maxDepth=2`，`timeLimitMs=180`，`candidateLimit=12`            |
| 唐僧   | `MinimaxAgent`    | `maxDepth=4` + 迭代加深，`timeLimitMs=350`，`candidateLimit=10` |

开局：`openingBook.ts`（花月/浦月等）+ 对称 + 人机/教师 mixed 随机——**已解决开局单调**，不解决中盘战术洞。

### 1.2 为什么认真下能赢唐僧

1. 叶子评估仍是粗粒度「赢法上已占子数」，对 **活三 / 冲四 / 双活三** 不够敏感。
2. 普通 αβ depth=4 **看不清**连续强迫序列（VCT 风格）。
3. 候选截断（10）可能剪掉关键防守点。

### 1.3 已否决 / 低优先级（本切片不做）

| 想法           | 为何不做（本切片）                                  |
| -------------- | --------------------------------------------------- |
| 只加深到 6–8   | 叶子差时收益差，主线程易卡顿                        |
| 只靠加长开局书 | 只改善前几手，不治中盘                              |
| 导入 ML Policy | 训练仓纯模仿对猪八戒约 10% 量级；不能当唐僧升级路径 |
| 「完美无敌」   | 自由五子先手优势复杂；产品目标改为「很难赢」即可    |

## 2. 目标体验

- 人机选 **唐僧**、自由规则、认真下：常见冲四/活三组合 **不再轻易漏防**；连续强迫胜（短 VCT）多数能走出或挡住。
- 沙和尚 / 猪八戒体感不因本改动变「突然变神」（紧急必应逻辑可复用威胁检测，但噪声策略保留）。
- 孙悟空可受益于同一套评估，但 **默认深度/时限可不升**，以保留四级梯度。
- 单步思考：唐僧建议仍 ≤ **800ms** 硬上限（可用 Worker）；超时返回当前最佳。

## 3. Phase A — 威胁模块（必做）

### 3.1 新增模块（建议路径）

`src/ai/threats.ts`（名称可调整，职责固定）：

| API（建议）                                 | 行为                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| `findWinningMoves(board, player)`           | 一手当场五连的点                                                        |
| `findOpenFourMoves` / `findFourThreatMoves` | 冲四 / 活四类强迫点（定义见下）                                         |
| `findOpenThreeMoves`                        | 活三（再下一手可成冲四/活四）的点                                       |
| `listForcedReplies(board, toPlay)`          | 若对方已存在「不挡则下一步可胜/可强杀」的威胁，返回必须考虑的防守点集合 |
| `listThreatCandidates(board, toPlay)`       | 进攻威胁点 ∪ 防守点，供根节点优先展开                                   |

**形定义（实现时写清并单测；允许与文献略有简化，但必须一致）：**

- **冲四**：存在一处落子使己方出现「四子连续且一侧可延伸成五」（对方必须堵，否则下步胜）。
- **活三**：存在落子后形成「两端可延伸的三」，对方不挡则己方可走成冲四/活四。
- 可先基于现有 `winsTable` + 空位枚举检测，不必上完整棋型引擎。

### 3.2 接入 `MinimaxAgent`

根节点走法顺序（高 → 低）：

1. 己方立即获胜点（有则直接下，勿搜索）
2. 必须防守点（对方冲四 / 活四等；漏则负）
3. 己方冲四 / 活三进攻点
4. 现有 `listOrderedCandidates` 启发分补齐，再按 `candidateLimit` 截断

搜索内部每一层展开前，同样优先插入「立即胜 / 必防」。

可选（推荐）：对唐僧增加 **短威胁搜索**——在根或浅层对「连续冲四」做专用 DFS（深度例如 6～10 半步，**只扩展强迫着法**），命中则直接采用；未命中再回退普通 αβ。时限共享 `timeLimitMs`。

### 3.3 沙/猪复用（小改，推荐）

`HeuristicAgent` / `ShaHeshangAgent` 已有 `URGENT_THREAT_SCORE` 活三修复：可将「必应」改为调用 `listForcedReplies`，避免两套判定漂移。沙和尚在必应集合外仍可 Top-K 噪声。

## 4. Phase B — 评估升级（必做）

文件：`src/ai/evaluate.ts`（或拆 `shapeScore.ts`）。

在现有 wins 计数分之上，对空点增加 **形分**（量级需调参，原则如下）：

| 形（己方） | 建议量级（相对现表）                           |
| ---------- | ---------------------------------------------- |
| 活三       | 显著高于「赢法上 2 子」                        |
| 冲四/活四  | 接近或超过现四连档                             |
| 眠三/冲三  | 中等加分                                       |
| 对方对应形 | 防守分略低于或等于进攻（保持现风格：进攻略重） |

叶子 `evaluateBoard` 与 `scoreEmptyCell` 共用形检测，保证搜索与猪八戒排序一致升级。

**调参约束**：猪八戒单步仍接近即时；不要让评估 alone 把猪八戒拉到接近唐僧（搜索深度仍是主梯度）。

## 5. Phase C — 唐僧参数与性能（推荐）

`src/ai/difficulty.ts` 建议起点（可按真机再调）：

| 参数                 | 当前唐僧 | 建议                                       |
| -------------------- | -------- | ------------------------------------------ |
| `maxDepth`           | 4        | **5**（或保持 4 + 威胁 DFS）               |
| `timeLimitMs`        | 350      | **600～800**                               |
| `candidateLimit`     | 10       | **12～16**（威胁点不计入截断或截断前必留） |
| `iterativeDeepening` | true     | 保持                                       |

若主线程卡顿：将 `MinimaxAgent` 重计算移入 **Web Worker**（`getNextMove` 仍 async）；Store / Pinia 仍不持有搜索树。

悟空保持 depth=2 / 180ms，除非四级梯度被破坏再微调。
